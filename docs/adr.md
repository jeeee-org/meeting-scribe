# ADR — 意思決定の記録

> 決定と理由を1件2〜3行で。詳細な根拠は NOTES.md と当日の docs/checkpoints/ にある。
> PROGRESS.md の行数上限（60行）に触れたため、2026-09-04 にこちらへ移した。
> 件数が増えて読みにくくなったら `docs/adr/`（1決定1ファイル）へ分ける。

- **001 録音は Rust + cpal 0.18、voice-input の資産を流用**（09-03）
  cpal は出力デバイスを入力として開くとループバックになる。実証済み。
- **002 アプリとして配布しない**（09-03）
  対象PCが pull できるので `cargo run` で足りる。配布・常駐化を v1 から外す。
- **003 耳を塞ぐ有線の機材を前提にする**（09-03）
  開放型だと回り込みで2系統の分離が壊れる。実測の分離は有線イヤホン42.5dB / H340 45.1dB。
- **004 2トラックの統合はサンプル数ではなく時刻で行う**（09-03）
  ループバックは再生中しかパケットを返さないことがあり、**同じ機械でも実行ごとに割れる**。
  条件分岐で吸収する道が無い。ただし実測では穴は70分で1.93%＝例外的。
- **005 使う音声エンドポイントは設定で固定する**（09-03）
  ジャックの抜き差しで一覧から消え、既定が耳に届かないデバイスへ移る。既定任せは無音を生む。
- **006 マイク側の時刻補正は「定数 + 離散欠損」**（09-04）
  ズレ ≒ 起動遅延 + Σ(underrun の欠損)。70分で1045回×6.9ms＝7.21秒が実測7.26秒と一致。
  経過時間に比例する係数は使わない。**相手トラックには当てはまらない。**
- **007 STT はまず whisper.cpp のビルド済み CPU バイナリで測る**（09-04）
  ビルドも Python も要らず容量が最小（バイナリ + 量子化モデルで約0.6GB）。
  業務ノートは空き3.4GBで Vulkan 一式を入れる余裕が無い。voice-input と同じエンジンなので
  結果が流用でき、速度が足りなければ GPU 化も同じ道を辿れる。
- **008 文字起こしは開発デスクトップ（RTX 5080 / CUDA）で行う＝2段構え**（09-04）
  業務ノートの CPU は実時間比 3.353 で要件に33倍届かず、公式の Vulkan ビルドが無いため
  この機械の GPU 化は自前ビルドで数GB要る。デスクトップは既存の実測で 0.0736（69分が5.1分）。
  **音声の受け渡しは USB SSD か同一 LAN 内の直接コピーに限り、クラウドは経由しない。**
  持ち出せない日は業務ノート単体で一晩かける経路を非常口として残す（VAD が前提）。
- **009 要約は「その日のうち」に間に合えばよい**（09-04）
  当初の「会議30分あたり3分以内」は暫定値だった。実運用の必要は緩く、この緩さが
  非常口（ノート単体で一晩）を選択肢として成立させる。デスクトップ経由なら大きく上回る。
- **010 要約はサブスクの Claude（`claude -p`）で行う**（09-04）
  停止後に数十秒かけてよいのでレイテンシ要件が効かず、voice-input が使わないと決めた理由が
  そのまま消える。API の従量課金がゼロになる代わり、開発で使う利用枠を会議の要約が食う。
  `ANTHROPIC_API_KEY` は使わない・設定しない。**プロンプトはソースに置いて版管理する**
  （要約の質はそこで決まるため）。会議の中身が外へ出る唯一の場所なので `--dry-run` を備える。
