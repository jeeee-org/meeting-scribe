# summarize — トランスクリプトを要約する

`merge-transcript` が出した `<stem>-transcript.txt` を読み、`<stem>-summary.txt` を書く。
実行手段は**サブスクの Claude（`claude -p`）**で、API の従量課金は発生しない（ADR-010）。

**WSL で動く。**

---

## ここがこのPJで唯一、会議の中身が外に出る場所

録音も文字起こしもローカルで完結しているので、外部送信はこの1箇所に閉じている。
だから**何を送るかを送信前に確かめられる**ようにしてある。

```
cargo run --release -- <stem> --dry-run
```

送る指示と入力の冒頭を表示するだけで、送信はしない。

`ANTHROPIC_API_KEY` は使わないし、設定してもいけない（CLAUDE.md）。
WSL 側の Claude Code が拾って、サブスクではなく従量課金で動く事故になる。

## 使い方

```
cargo run --release -- <stem>                  要約して <stem>-summary.txt を書く
cargo run --release -- <stem> --dry-run        送る内容を見るだけ
cargo run --release -- <stem> --model=opus     モデルを指定する
```

30分の会議で十数秒。60分でも数十秒で終わる。

## 出力

```
【一言サマリ】
在庫連携を日次バッチからリアルタイム連携へ変更する件について、対象範囲・実装方針を詰めた打ち合わせ。

【決まったこと】
・全商品ではなく、まずは主力の3カテゴリだけを対象にする（負荷が読めないため）[00:35.5]

【自分のToDo】
・APIの仕様書を作って共有する。来週の水曜まで [01:05.3]

【相手のToDo】
・負荷試験の環境を用意する（期限の言及なし）[01:14.8]

【未解決の論点・次回への持ち越し】
・エラー時のリトライ方針。相手が持ち帰り、次回はここから始める [01:44.0]

【気になった点】
・[02:01.2]「あとサンプル数についてですが…」——文脈とつながらず、誤変換の可能性がある
```

### 時刻はトランスクリプトの表記をそのまま写す

`grep -F "[01:44.0]" <stem>-transcript.txt` で**原文に戻れる**ようにするため。
最初の実装ではモデルが `[00:01:44]` へ形式を変換してしまい、検索しても見つからなかった。
時刻を添える目的そのものが損なわれるので、プロンプトで明示的に禁じている。

### Markdown を使わない

そのまま他所へ貼れる素のテキストにする（グローバル規約 §8）。見出しは【】、箇条書きは・。
`**強調**` は貼った先で `**` ごと表示されるだけで、読みにくくなる。

## プロンプトはソースに置いてある

`src/main.rs` の `INSTRUCTIONS`。**要約の質はここで決まる**ので、版管理して実運用で育てる。
現在の指示が押さえているもの:

- **書かれていないことを書かせない。** 該当がなければ「言及なし」。
- **期限を勝手に作らせない。** 話されていなければ「期限の言及なし」。
- **音声認識の誤りがある前提**にする。判断がつかない語は原文のまま残させ、
  怪しい箇所は【気になった点】に時刻つきで挙げさせる。
- 時刻の表記を変換させない（上記）。

## まだ無いもの

- **語彙辞書** — 固有名詞・術語の補正（REQUIREMENTS.md）。実運用で誤変換が溜まってから作る。
- **段階要約** — 長い入力は中盤が薄くなる。60分＝2万字程度はコンテキストに余裕で収まるので
  上限の問題ではないが、**品質対策としては有効**。実際に質が落ちてから入れる。
